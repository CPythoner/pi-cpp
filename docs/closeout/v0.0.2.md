## 6. Retry 兼容边界

pi `v0.80.0` 的 OpenAI 路径使用 openai-node 6.26.0。closeout 时明确冻结以下语义：

- 408 / 409 / 429 / >=500 retryable；
- `x-should-retry` 显式覆盖 status 分类；
- `retry-after-ms` 优先于 Retry-After；
- Retry-After 支持数字秒和 HTTP-date；
- 无 server delay 时使用 500ms 起步、指数增长、8s cap + jitter；
- transport failure 只在尚未获得可用 response / 尚未开始 stream 时 retry；
- retry sleep 本身不会被 AbortSignal 提前唤醒，取消在 delay 结束、下一次请求前观察；
- v0.0.2 OpenAI 路径为兼容固定基线故意忽略 `StreamOptions::maxRetryDelay` 对 server Retry-After 的截断。

这些属于兼容行为，不应在后续版本未经 differential 证据就“改进”。
